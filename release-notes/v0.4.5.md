# xray-pilot v0.4.5

用户增删改走 xray gRPC 即时生效，**不再重启 xray**——消除「改一个用户 → 全节点重启 → 断所有现有连接」的抖动。

## 新增

### gRPC 即时生效（用户增删改不重启）

之前每次建/删/启停用户、改分组、重置 UUID，面板都会把相关节点标记为「待同步」，随后通过 SSH 推送完整配置并 `systemctl restart xray`。重启会瞬断该节点上**所有用户**的现有连接。

本版接入 xray 的 gRPC `HandlerService.AlterInbound`，对运行中的 xray 即时增删用户：

- **即时生效**：通过 SSH 隧道访问节点本地的 xray gRPC API（127.0.0.1:10085），毫秒级 AddUser/RemoveUser，不重启、不影响其他用户
- **双写持久化**：同时把最新 `config.json` 写到节点（**不重启**），保证 xray 重启后用户状态可恢复
- **安全降级**：任一节点的 SSH/配置上传/gRPC 失败，自动回退到原有「标记漂移 + 重启同步」路径，绝不丢操作

覆盖的用户操作：**新建 / 删除 / 启用 / 禁用 / 改分组 / 重置 UUID**。其中改分组用「旧/新节点集差集」对账，只触碰真正变化的节点（加入新分组的、移出的），不波及无关节点。

### 开关与启用

- 新增系统设置 **「gRPC 即时生效（用户增删不重启）」**（Settings → Xray 日志区）
- **默认关闭**：关闭时行为与 v0.4.4 完全一致（标记漂移 + 重启同步）
- 打开后即享受不重启；建议先在测试节点确认无误再全量开启

## 边界（有意为之）

- **漂移检测不变**：仍走 SSH 读取远端 `config.json` 比对，未改 gRPC（StatsService 查不到 idle 注册用户，对账会漏报）
- **不做节点/协议的 gRPC 动态增删**：新增协议、新增节点仍走完整 SSH 同步（含重启）
- **Hysteria2 跳过**：不在 xray-core，gRPC 无法管理，相关 inbound 自动忽略
- **用户名（email）变更**：涉及跨节点 email 改动，回退到全量重启同步（罕见操作）

## 升级

- 无破坏性变更；新设置项默认 off，不开启则行为与 v0.4.4 一致
- 无 schema 变更
- 前置条件：节点 xray 配置需含 API inbound（127.0.0.1:10085）——该 inbound 自 v0.2.x 起已包含在生成配置中（流量统计功能已在用），正常同步过的节点均满足

## 其他

- 新增 `cmd/grpcsmoke` 运维冒烟工具：不依赖面板，用显式 SSH 参数直连节点验证 gRPC 用户增删（`go run ./cmd/grpcsmoke -h` 看用法）
