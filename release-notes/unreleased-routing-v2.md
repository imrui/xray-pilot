# 未发布：路由配置与安全发布 V2

独立分支 `codex/routing-config-v2`，不包含仪表盘统计分支的改动；尚未发布正式版本。

## 新增

- 管理后台增加“路由配置”：模板草稿、不可变版本、历史引用、全局／分组／节点绑定、字段覆盖和脱敏配置来源预览。
- 支持“强制 IPv4 域名”“强制 IPv6 域名”两组独立规则及受校验的自定义路由。未命中规则使用普通 `freedom / direct`，两组列表为空时不强制地址族。
- 移除新版模板的 IPv6 开关；强制 IPv6 只作用于对应目标域名，与客户端通过 IPv4 或 IPv6 连接节点无关。无 IPv6 出口的节点在同步前拒绝含强制 IPv6 的配置；强制地址族均不回退，IP 字面量不做地址族转换。
- 系统保护规则、自定义规则、强制 IPv4 域名、强制 IPv6 域名依次匹配；两组域名规则重叠时 IPv4 优先。
- 预置可直接选择的“系统默认路由”和“AI 工具 / 流媒体分流”模板，后者包含 8 条 IPv4 与 3 条 IPv6 起始规则，不默认纳入覆盖范围较广的 `domain:google.com`。参考域名导入与预设初始化共用同一目录，支持复制草稿为独立模板。
- 预设仅补齐缺失内容，升级及重启不重复创建、不覆盖管理员修改、不自动绑定节点。页面标明 IPv6 出口要求及节点／分组／全局的继承关系；恢复默认直连时仍须检查节点覆盖。
- 增加用户／节点／全局的客户端 UDP 443 策略，不支持等价表达的订阅格式明确提示限制。
- 增加节点预检、SNI 诊断、自定义配置路径、批量任务、失败重试和结果核对。

## 操作界面

- 节点域名覆盖明确区分“继承模板”“自定义列表”“清空规则”：默认继承，展示所选固定版本或分组／全局继承模板中的只读域名；自定义替换整组列表，空白输入不能误保存为清空。现有节点覆盖保持不变。
- 模板来源预览只读，不写入绑定或同步任务；切换来源及版本时更新继承内容，加载失败和继承冲突明确提示。客户端 UDP 443 策略补充两种 Vision flow 的说明及订阅格式限制。
- 路由选择项统一称为“路由来源”，基础配置方式明确标为“基础路由（不使用模板）”。节点列表、来源摘要、配置预览及接口提示统一使用该名称，并说明同步时按基础规则生成配置，不使用模板或节点路由覆盖。
- 路由配置采用与协议配置一致的列表和编辑抽屉；模板侧可批量配置节点，保留每台节点原有覆盖、路径和订阅策略。
- 模板的“配置节点”抽屉区分点击查看与勾选批量操作；点击节点直接预览已保存的路由与出站，也可打开完整配置。一个节点只选择一份路由模板，更换模板替换旧规则，同时保留多个协议及节点覆盖。
- 节点列表统一管理协议与路由，保留完整配置预览、单节点同步、批量同步及同步待处理节点；顶部待同步提示统一跳转节点列表。
- 同步记录、预检、SNI 诊断和恢复操作归入节点管理；任务支持分页及按节点筛选，关闭窗口后继续执行。单节点提交失败不会阻止其他节点。
- 分组编辑提供路由继承设置，全局默认在路由配置中管理。保存前可预览实际影响节点，预览不提交绑定或同步状态。
- 完整配置预览增加来源与运行确认对照；明确区分已保存的期望配置和远端运行状态。没有历史配置快照时，不生成不可靠的逐行差异。
- 用户、节点和全局客户端 UDP 443 策略分别归入对应设置；健康探测地址移至系统设置的节点与同步区域。
- 保存反馈区分手动与自动同步；模板新版本不自动升级现有绑定。抽屉保留未保存提醒，并支持键盘关闭与焦点返回。

## 同步与迁移

- 存量节点保持基础路由（不使用模板，内部标识 `legacy`）；新建节点继承已配置的全局默认。首次初始化的系统默认模板使用普通直连，升级不改写已有全局绑定。
- 旧模板版本和健康恢复快照保留原有 IPv4 兜底语义；编辑旧模板时转换为新版草稿，原先因关闭 IPv6 而走 IPv4 的列表会归入强制 IPv4 域名。保存、发布并选择新版本后才切换行为，历史版本不变，发布不自动升级现有绑定。
- 新版模板拒绝旧版 IPv6 开关覆盖；节点编辑会提示显式移除并检查两组域名列表。现有节点覆盖继续按列表替换规则生效，不会被换模板操作静默清除。
- 完整发布采用节点锁、数据库租约、目标内核预检、原子替换、健康验证和持久化任务。
- 用户热更新先持久化当前授权，再应用 gRPC 差异；部分失败不再误报成功。
- 健康检查失败恢复最近健康路由策略，重新生成当前用户和密钥，避免复活被撤销的授权；恢复失败停止自动循环。
- 换机清理旧机器回执；删除最后一个已管理协议可撤销旧监听；新 Reality 密钥默认生成非空 shortId。

## 评审修复

- 健康或重启失败时原子恢复符合当前授权的旧配置；恢复不改写管理员的模板绑定和期望版本，失败目标保持待同步并延迟重试。
- 恢复队列获锁后重读状态，热更新成功后不重复重启；租约占用重新排队，失效回执不能确认成功。
- 已存在目标文件时只读核对运行回执，响应丢失不盲目重复写入或重启。
- 分组冲突按节点报告，只有有效配置变化的节点进入同步；覆盖按实际模板校验。
- 显式阻止 UDP 443 保留 Clash／sing-box 的标准 Vision 条目；运维代理保留原有 direct 地址族语义。
- 过期撤权须全部节点确认生效或确认停止才打标；离线节点保留待处理，停止服务有告警。
- 首装和换机按安装器新建配置的 SHA-256 建立一次性基线，兼容带入站的样例配置；安装前已有配置、安装后被修改的配置均不自动接管。首次预检失败可按已确认基线重试。
- 自定义目标 IP／CIDR 规则可正常下发和恢复；私网保护、来源白名单与入站保护规则仍须符合当前授权。
- 过期摘除识别已恢复服务的文件及进程回执；当前授权已确认时保持服务运行，失败路由目标继续待同步。缺少有效回执或授权已变化时仍执行停止保护。
- 修复仅剩管理接口时空端口列表导致健康检查异常和误回滚的问题。
- 为暂存配置、回滚配置和健康探测客户端显式指定 JSON 格式，修复真实 Xray 无法识别临时文件格式而拒绝首装发布的问题。
- 健康配置备份兼容 Python 3.6；代理探测适当延长单次时限并最多重试一次，始终经过本次测试代理，不受环境中的免代理设置干扰。
- 一键接入支持 `NODE_IP` 指定面板可达的 IPv4／IPv6 地址，适用于局域网或 NAT 环境；非法地址在修改 SSH 配置前拒绝。
- 当期望文件已经由恢复或用户热更新生效时，按已确认的文件和进程进行原地健康复核，不重复写配置或重启；缺少运行证明、进程变化或健康失败仍保持未确认。
- 相同内容的快速核对也验证 systemd 配置路径，避免把未被服务使用的同内容副本误判为已应用。

安装基线登记需要本分支配套的一键接入脚本。旧脚本仍可登记节点，但不会获得覆盖现有配置的初始化许可。

## 验证与限制

默认部署继续使用 SQLite，PostgreSQL 是可选后端，不是部署或验收的前提。

本地 Go 测试、真实 Xray 26.3.27 配置预检，以及 Ubuntu 18.04／24.04 的 API 与 SSH 节点测试已执行；覆盖首装、真实 Reality 流量、自定义 IP 规则、无 IPv6 出口时的预检保护、重复发布、手工配置漂移保护、批量任务隔离、健康失败回滚、回滚后的过期撤权、用户热更新、模拟换机和模板继承。SQLite 接口备份、下载和独立副本恢复启动已验证。

本轮界面调整已通过 18 项 DOM 交互测试、前端静态检查与构建；默认继承、模板替换、恢复继承及多个协议共存的完整配置已通过真实 Xray 检查。新版策略覆盖空列表默认直连、单地址族、双列表重叠顺序、自定义 IPv6 规则及旧策略恢复兼容；两台无 IPv6 出口的 Linux 节点已通过 IPv4 预检、IPv6 预检拒绝和运行文件／进程不变检查。默认 direct、强制 direct-v4 已通过真实代理请求和出站标签验证，健康失败时恢复原文件与代理可用性已验证。预设补齐、重命名与修改保留、同名冲突、模板复制及默认模板与节点覆盖的关系已覆盖。未进行浏览器视觉验收。Linux arm64、实际 IPv6 出口及其他客户端完整矩阵尚未验证；现有结果不能代替这些环境的上线验收。
