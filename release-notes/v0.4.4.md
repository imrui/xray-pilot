# xray-pilot v0.4.4

两个节点级配置覆盖能力修复：Reality 的 SNI/指纹现在可按节点覆盖，日志级别也可按节点单独调。

## 修复

### 节点级 SNI / Fingerprint 覆盖现在真正生效

之前订阅 URI、Clash、sing-box、xray inbound 四处生成时，SNI 和 TLS 指纹**只从协议模板读取**，节点密钥材料结构体里压根没有这两个字段。所以在节点协议管理里手动改 SNI 不会生效，订阅拿到的还是模板的旧值。

现在 `RealityKeyMaterial` 新增 `sni` / `fingerprint` 字段，四处生成统一走 `EffectiveRealitySNI` / `EffectiveRealityFingerprint` helper，取值优先级：

```
节点密钥覆盖  >  协议模板  >  默认（www.microsoft.com / chrome）
```

某个节点要改 SNI：进「节点协议管理」抽屉 → 编辑 Reality 密钥 JSON 的 `sni` 字段保存（已绑的需先解除锁定）→ 点同步。前端「一键生成」现在也会把模板的 sni/fingerprint 带出来作为可改初值。

### 节点级日志级别覆盖

之前日志级别只有系统设置里一个全局开关，要给单个异常节点开 `debug` 排障，会同时拉高所有节点的日志量。

现在节点编辑抽屉新增「Xray 运行参数 · 日志级别」下拉：留空继承系统设置，也可单独设为 `debug` / `info` / `warning` / `error` / `none`。只影响该节点，同步后生效。

## 升级

- `nodes` 表新增 `log_level` 列（GORM AutoMigrate 自动加，nullable，老数据为空即继承全局，零侵入）
- 无破坏性 API 变更
- 已配置过的节点若要用上节点级 SNI，需重新进抽屉补 `sni` 字段并同步；不补则行为与之前一致（继承模板）

## 注意事项

- 两处覆盖都需点「同步」下发到节点才生效
- 节点级 SNI 覆盖遵循项目既有 per-node 覆盖约定：所有消费方统一走 helper，不各自读模板（与 `effectiveKeyPort` 同一模式）
