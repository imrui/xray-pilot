# 版本化路由模板（Schema v1/v2）、三级继承与事务性配置同步架构

- **日期**：2026-11-16（涵盖 `v0.7.0` 架构重构与 `v0.7.1` / `v0.7.2` 同步失效范围及兼容性收敛）
- **状态**：Implemented（已落地于 `v0.7.0`、`v0.7.1`、`v0.7.2`）
- **关联模块**：`internal/entity/routing.go`、`internal/xray/routing_policy.go`、`internal/service/routing*.go`、`internal/service/config_*.go`、`internal/service/sync.go`、`pkg/ssh/xray_*.go`、`frontend/src/pages/Routing.tsx`

---

## 1. 背景与建设目标

在 `v0.7.0` 之前，所有节点的 `routing` 与 `outbounds` 均为硬编码直连 + 私网屏蔽，无法针对不同节点或业务分组配置 IPv4 / IPv6 分流策略，且 SSH 同步缺乏远端内核预检、并发写入租约与健康失败自动回滚机制。

本阶段完成了两大基础架构升级：
1. 建立**草稿与不可变版本分离的路由模板**，以及 `节点 > 分组 > 全局` 的三级继承与覆盖体系。
2. 建立**期望态 / 磁盘态 / 运行确认态分离的事务性配置下发管线**，确保坏配置绝不覆盖线上健康服务，且回滚绝不复活已撤销的用户权限。

---

## 2. 路由模板、三级继承与地址族策略模型

### 2.1 草稿、不可变修订与绑定分离
- **`RoutingTemplate` & `RoutingTemplateRevision`**：编辑模板仅修改 `Draft` 草稿，不影响任何已绑定节点；执行发布才生成单调递增且不可原地修改的 `Revision` 快照。旧版本保留供审计与回退使用，被引用的模板禁止硬删除。
- **`RoutingBinding` 三级解析优先级**：
  1. `mode == "legacy"`（仅限节点）：保持旧版基础直连与协议保护规则，不套用任何模板或覆盖（保障存量节点升级零行为突变）。
  2. `mode == "template"`：显式固定绑定某模板的指定 `revision`（模板后续发布新版不会导致节点自动漂移）。
  3. `mode == "inherit"`（节点新建默认）：优先检查节点所属的全部启用分组；若多个分组绑定了不同模板或不同修订，**显式报告分组冲突并阻断该节点生成**（绝不按数据库顺序盲目挑一）；若分组均未指定路由，则回退全局默认绑定。
- **节点覆盖三态语义（`Overrides`）**：字段缺省或 `null` 表示继承模板固定版本；非空数组替换对应列表；显式空数组 `[]` 表示在本节点清空该组规则（与继承严格区分）。切换模板版本时保留节点已有覆盖并重新校验兼容性。

### 2.2 域名分流语义演进（`SchemaVersion: 1 -> 2`）
- 废除早期易产生歧义的节点全局 IPv6 布尔开关与全流量 `ForceIPv4` 兜底，演进至 `SchemaVersion: 2`：
  - **匹配优先级**：`系统置顶保护规则（api + allow_private 代理直连 + geoip:private 屏蔽 + 代理白名单）` → `受校验自定义规则` → `强制 IPv4 域名（direct-v4 / ForceIPv4）` → `强制 IPv6 域名（direct-v6 / ForceIPv6）` → `未命中流量默认普通 direct 直连`。
  - **严格地址族与前置能力检查**：`direct-v6` 采用严格 `ForceIPv6`（不静默回退 IPv4、不转换 IP 字面量）；凡配置需要 IPv6 出站（`RequiresIPv6() == true`），同步与预检阶段先探测目标节点默认 IPv6 路由与出口连通性，不满足则在替换文件前直接拒绝。
  - **订阅协议纯净性**：移除开发期试验的客户端 `udp443` 订阅策略字段，VLESS Reality 统一输出标准 `xtls-rprx-vision`，确保 Base64 / Clash / sing-box 订阅内容与服务端路由策略彻底解耦。

## 3. 事务性配置下发、真实握手验证与安全回滚

### 3.1 三态追踪与并发互斥（`NodeConfigState` & `ConfigDeployment`）
- 每台节点独立记录：`DesiredHash/Revision`（数据库期望）、`DiskHash/Revision`（远端落盘确认）、`RuntimeHash/Revision` + `ProcessID` + `VerifiedAt`（经健康检查确认的运行回执）以及 `LastHealthyPolicy`。
- **多层并发防覆盖**：进程内 `lockNode(nodeID)` 互斥锁 + 数据库 `AcquireConfigLease` 租约 + 远端配置目录 `flock` 文件锁 + 提交前 `BeforeApply` 期望版本二次核对。响应丢失重连后优先通过远端文件哈希与状态回执原地对账（`Reconcile`），相同已确认配置绝不重复写入重启。

### 3.2 远端预检、原子替换与真实协议探测（`pkg/ssh`）
1. **同目录 `.json` 临时预检**：配置内容通过 SSH `stdin` 写入目标配置同目录下的唯一临时文件（强制保留 `.json` 后缀并指定 `-format json`，兼容 Xray `26.3.27` 与 `26.11.9+`），调用节点真实 Xray 二进制执行 `-test` 校验，未通过则立即清理临时文件并中止，线上进程零扰动。
2. **首装与手工漂移保护**：仅首装/换机登记的一次性基线或与面板上次确认一致的文件允许自动替换；发现外部手工修改导致基线不符时报告漂移冲突，拒绝盲目覆盖。
3. **端到端代理握手验证（`xray_health.go`）**：重启服务后，不仅检查进程存活、监听端口与 `10085` 管理口，当存在有效 VLESS/Trojan 用户时，还在远端拉起临时测试客户端，通过真实 Reality/TLS 握手请求公网 HTTPS `probe_url`（校验公网 IP 防私网重定向）。

### 3.3 回滚绝不恢复已撤销权限（核心安全红线）
- 当重启或真实代理握手验证失败时，触发自动回滚：将上一份已验证健康的路由策略（`LastHealthyPolicy`）与**当前数据库最新的有效用户列表、当前有效节点密钥**重新合成恢复配置写回并启动服务。
- **两条铁律**：
  1. 已删除、禁用、过期或重置了 UUID 的用户权限绝不会因为路由回滚而在节点上“复活”。
  2. 自动恢复仅挽救线上服务可用性，**绝不篡改管理员在数据库中保存的目标模板绑定**，节点保持“待同步/已回退”提示供管理员排查修正，且单次故障最多自动回滚一次，杜绝无限重启风暴。

## 4. 变更失效范围最小化与统一操作流（v0.7.1 / v0.7.2）

1. **精准计算同步失效范围**：
   - 分组成员增删、启停或删除仅标记成员关系实际变更的节点；修改分组名称/备注不触发同步。
   - 单节点修改协议端口、密钥或绑定解绑仅失效该目标节点；修改共享协议模板仅失效已绑定节点（若仅改模板默认端口，跳过已有独立端口覆盖的节点）。
   - 保存加密私钥时对比内存解密明文，消除 AES-GCM 随机 Nonce 导致的虚假配置变更；所有配置修改与同步状态更新置于同一数据库事务内原子提交。
   - 节点和用户的资料编辑仅写入请求指定的列。用户授权在事务内按启用分组和可接收订阅用户的入站计算节点差集，重命名或换 UUID 时同时覆盖旧、新授权节点。每个节点每次事务只递增一次配置修订号。
   - 到期摘除按用户、节点持久化待办。到期前移组留下的旧节点由当前配置的同步回执清除，尚未确认的旧节点继续参与到期撤权。扫描按节点合并操作，取得当前授权回执或确认停服后才消费对应批次的待办。最后一个节点完成后写入用户摘除时间。SQLite 和 PostgreSQL 的授权事务都覆盖成员关系变更与待办登记。
2. **统一页面分工**：
   - 「路由配置」页专注模板草稿、版本发布与使用关系（对齐「协议配置」抽屉交互）；所有单节点同步、批量同步、完整配置预览、预检与同步历史统一收口于「节点管理」页，消除双工作区割裂。
