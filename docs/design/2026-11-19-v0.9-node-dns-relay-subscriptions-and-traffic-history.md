# 节点 DNS 同步、内网中转订阅与已删除节点名称

状态为 **Implemented**（v0.9.0）。

## 一、节点 DNS 同步

节点的 `IP` 是 SSH 管理地址，`Domain` 是客户端优先使用的连接域名。管理员更换 IP 后，客户端应能沿用原域名。首期支持 Cloudflare 的一个 Zone，仅接管已有记录（不自动创建或删除记录），支持手工编辑节点和使用安装令牌「更换服务器」两条改址路径。

### 配置与绑定

- 「系统设置 → 节点 DNS 同步」提供总开关、服务商、Zone ID、API Token 和「测试连接」。超级管理员管理凭据与记录绑定；普通管理员在节点页可只读查看 DNS 绑定与同步状态，并通过修改已绑定节点的 IP 触发同步。新装和升级默认关闭，所有节点起初均未绑定。
- Token 使用面板 MasterKey 加密，通过独立的凭据接口写入。通用设置的读写接口均排除该字段；前端只接收「已配置」状态，留空保存沿用原密文，清除是独立操作。测试连接只读取目标 Zone 的记录，界面明确显示「读取成功」，实际写入结果以同步回执为准。Token 使用仅限目标 Zone 的 DNS 编辑权限。[Cloudflare 权限模板](https://developers.cloudflare.com/fundamentals/api/reference/template/)
- 在节点编辑页选择「绑定 DNS 记录」。按完整域名精确查询，IPv4 匹配 A，IPv6 匹配 AAAA。首次绑定预览域名、记录类型、远端当前值与节点 IP：只要远端记录唯一且类型匹配即可保存绑定；若远端值与当前节点 IP 不一致，明确提示差异并允许管理员确认绑定后手动触发一次同步（适配先换机再补绑的场景）。同名同类型多条、缺记录、CNAME 均显示具体原因，管理员先在 Cloudflare 整理记录。每条记录仅允许绑定一个节点。[Cloudflare 查询记录接口](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/list/)
- 绑定保存 Zone ID、记录 ID、规范化域名、地址族和最近确认的 IP。编辑节点时若更换域名或跨地址族修改 IP，允许正常保存节点，同时自动将原绑定标为「需重新绑定」并停止自动同步。更换 Zone 后同样要求重新绑定。取消绑定或删除节点只解除面板托管，Cloudflare 保留原记录。未绑定的域名继续由管理员自行维护。

### 更换 IP 时的行为

1. 两个改址入口（手工编辑节点需补传 `actor`）在保存节点 IP 的同一数据库事务内登记 DNS 的最新期望值、版本和触发者。只对已启用、已绑定且地址值实际变化的节点排队；**节点的禁用/开启切换不触发任何 DNS 变更**。换机注册只可更新令牌目标节点已经绑定的记录，且直接排队 DNS 更新，不阻塞等待新机 Xray 同步完成。界面可先显示「IP 已保存，DNS 待同步」。
2. 后台按「事务提交后立即异步唤醒 + 进程启动扫描未终态/在途任务 + `scheduler` 周期兜底」模型运行，按记录使用独立串行锁，提交数据库事务后才请求 Cloudflare，**严禁在持有节点 `lockNode` 或 `ConfigLease` 期间执行外部 HTTP 调用**。写前重读开关、绑定、最新期望值和远端记录。远端已是目标 IP 就确认成功，仍为上次确认值才执行 PATCH。遇到外部改值、缺失、重复或已重建的记录，进入「需重新绑定」。管理员须重新预览并确认远端记录，之后才可手动同步。PATCH 仅提交 `content`（及 API 必填路由字段），保留远端原有 TTL、代理开关、备注等设置，不得以零值覆盖。[Cloudflare 更新记录接口](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/edit/)
3. 每条在途请求持久化其目标与版本。请求超时或进程重启后先回读远端，再决定是否重发。连续改址时，先核对上一次在途结果，再处理最新值；旧回执仅用于确认远端曾写入的值，不能把新的期望标为完成。关闭开关或解绑后停止后续写入；重新启用时列出有差异的绑定，由管理员发起核对。
4. 对超时、限流和暂时性服务错误最多自动重试两次，限流遵循服务商返回的重试时间。权限错误和记录冲突直接显示原因。在节点详情提供「重试」或「重新绑定」。操作日志保留节点、变更前后 IP、结果和 Actor，并对凭据脱敏。
5. DNS 与 Xray 配置分别显示结果。DNS 失败时保留已保存的新管理 IP，方便通过 SSH 排障。「DNS 已更新」表示 Cloudflare 已确认该记录，客户端仍可能在 TTL 内使用缓存。

## 二、内网中转订阅

功能名采用 **内网中转订阅**，用户字段采用 **内网中转订阅 ID**。名称告诉用户何时使用，后续更换中转软件也可沿用。Xray Pilot 负责向用户分发已有地址；账号开通、授权、到期和撤销由中转服务管理。

| 位置 | 行为约定 |
|---|---|
| 系统设置 → 订阅 | 增加「启用内网中转订阅」和「内网中转订阅地址前缀」。默认关闭，启用前必须填写有效前缀（跨字段结合 DB 已有值校验）。关闭时保留前缀和已录入的用户 ID，并同时在用户页和后续飞书消息中隐藏。 |
| 用户创建、编辑 | 增加可选「内网中转订阅 ID」，允许清空；非空值要求全局唯一以防复制粘贴串号。功能启用且 ID 格式有效时，字段标签右侧用主题绿色等宽小字预览完整地址，随输入更新。预览使用用户列表接口返回的有效前缀，以可选中复制的纯文本呈现，窄屏自动换行。独立于面板用户名、UUID 和订阅 Token；单独修改此字段只更新用户资料，不触发节点热同步或漂移标记。 |
| 用户列表 | 「订阅」独立成列，提供复制、二维码和打开订阅页。启用内网中转订阅时，在其右侧显示「内网中转订阅」列，提供复制和二维码。未填写 ID 时显示「未配置」。关闭时收起该列，编辑页仍可维护 ID。 |
| 用户订阅页 | 在主订阅下方、节点列表上方展示「内网中转订阅」及内网提示。地址行与节点行共用复制按钮和二维码图标。有效用户即使暂时没有面板节点也能看到自己的内网中转订阅地址。 |
| 飞书订阅信息 | 在个人订阅卡片现有链接下方追加标题、内网提示及可复制的完整地址。单用户推送、批量推送和机器人私聊取订阅共用相同逻辑，批量发送逐个收件人生成地址。 |

**地址生成。** 系统保存前缀，用户保存一个可空的 `relay_subscription_id`，完整地址由后端统一生成。前缀接受带主机的绝对 HTTP(S) URL，允许内网 IP、端口与路径，拒绝内嵌凭据、查询串及片段。ID 区分大小写，必须是单个路径段；首期接受字母、数字、短横线、下划线和点，拒绝单独的 `.`、`..`。忽略输入首尾空白，统一处理前缀末尾斜线。例如前缀 `http://192.168.0.2:2096/sub/` 和 ID `u002abc` 生成 `http://192.168.0.2:2096/sub/u002abc`。面板只构造地址，无须能连到内网。

**分发条件。** 用户订阅页与飞书共用同一判断：全局启用、前缀与个人 ID 有效、用户满足 `EffectiveActive(now)`。任一条件不满足即省略整个中转区块，包括 HTML 数据属性和飞书卡片字段。机器订阅（Base64、Clash、sing-box）继续只输出其原有配置。关闭分发只影响之后的页面和消息；已经复制、扫码或发出的地址，其有效期由中转服务决定。

**二维码与离线可用。** 列表直接复制默认地址。后台和用户页的内网中转订阅二维码弹窗每次打开时默认选择「订阅」，可切换至 JSON（`?format=json`）或 Clash（`?format=clash`）。后台普通订阅弹窗和个人页主二维码均可选择默认订阅、V2Ray（`?format=v2ray`）、Clash（`?format=clash`）或 sing-box（`?format=singbox`）。两种弹窗均在完整地址下方单独一行提供「复制地址」和「保存二维码」，按当前选项复制链接或导出 PNG。个人页「扫码订阅」在二维码下方显示当前格式对应的客户端说明。两栏底部的通栏地址行在左侧显示可手动选中的完整链接，右侧并排放置「复制」和「二维码」（保存图片），选择 Clash 时还会显示「导入」。窄屏可横向滚动查看完整链接。浏览器关闭 JavaScript 时，同一区域列出所有格式的完整地址。主订阅与内网中转订阅各自独立选择格式。两个页面的订阅二维码下载文件统一命名为 `xray-pilot-<用户名>-<订阅类型>-<格式>.png`，默认格式标为 `default`。二维码脚本随面板内嵌，可在内网离线生成。二维码无法加载或生成时，中转订阅弹窗仍可切换格式并复制地址，节点弹窗可复制该节点的链接。内网中转订阅地址和个人 ID 按订阅凭据处理，操作日志只记录修改结果。

## 三、已删除节点在流量图中保留名称

目前 `traffic_samples` 和 `traffic_polls` 只存节点 ID，统计服务从现存节点表取名称，删除后只能显示「已删除节点 #24」。柱子下方的 `#8` 表示排名第八，与节点 ID 是两个值。

- 在 `NodeRepository.Delete` 的现有级联事务内读取最终名称，写入删除快照（节点 ID、名称、创建时间、删除时间）。归档写入失败则整笔删除回滚。在删除前曾改名的节点保留最后的名称。换机沿用原节点 ID，无需归档。
- 流量统计批量读取所选区间涉及的已删除节点，排行、趋势图例、提示及点击柱形后的筛选项共用同一身份信息。DTO 显式携带 `deleted` 标识，前端据此渲染：宽度充足时展示「usw2 · 已删除 · ID 24」；窄屏优先显示名称与删除标记，提示中展示完整信息。排名单独写「第 8 名」。归档只用于历史流量展示，当前节点数（`TotalNodes`）、健康统计和运维节点列表仍仅以现存节点为准，不得将归档混入现存节点计数。
- 流量按节点 ID 聚合，因此新节点须使用从未分配过的 ID。为避免 SQLite 重建存量表的高风险迁移：
  - **SQLite**：依托单连接串行写保证，在 `NodeRepository.Create` 事务内跨现存节点、删除快照、流量样本与采集记录取 `MAX(id) + 1` 显式写入 `node.ID`。分配时同时保留 `sqlite_sequence` 中已有的更高水位，兼容历史流量清理后的旧库。
  - **PostgreSQL**：启动迁移时将 `nodes` 序列下限通过 `setval` 推进至上述四表最大 ID 之上（已有更高序列值则保留）。
  - 创建、删除和重新创建的集成测试覆盖两种数据库。
- **不处理存量历史数据补录**：升级前已删除的节点（如 `#24`、`#7`）继续沿用「已删除节点 #ID」展示，仅对上线后新删除的节点记录名称快照。

## 实施顺序与验收

| 顺序 | 可独立验收的结果 |
|---|---|
| 1. 删除快照与仪表盘 | 节点改名后删除，排行、趋势图例与点击下钻均能识别最终名称、`deleted` 状态和真实 ID；现存总节点数不受影响。新建同名节点后 ID 不复用、两者流量分开；升级前无快照旧数据保持「已删除节点 #ID」正常展示。 |
| 2. 内网中转订阅 | 核对后台复制值、二维码解码值和飞书文本三者一致。测试缺 ID、重复 ID 拦截、过期瞬间、总开关关闭、无面板节点、两名用户批量推送，以及断外网环境下页面零外链加载与离线生成二维码。 |
| 3. Cloudflare DNS 同步 | 用模拟 API 覆盖手工及换机改址、禁用/启用不触发 DNS、改域名/地址族标为需重新绑定、首次绑定远端值差异确认、连续改址、请求超时后实际已写入、重启恢复、限流、权限不足、记录冲突和解绑。核对未托管节点无 API 调用，TTL 和代理状态保留，通用设置及日志均不含 Token。 |
