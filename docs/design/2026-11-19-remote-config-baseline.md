# 远端配置核对与基线接管

状态为 Implemented。

普通同步遇到 `DRIFT_CONFLICT` 时停在覆盖前。管理员可从节点列表或失败任务进入该节点的诊断抽屉，超级管理员可在此核对并接管远端文件。

## 核对与认领

1. `inspect-baseline` 礼让活跃配置租约，在节点进程锁内按实际配置路径读取最多 16 MiB。核对只读数据库。原始字节 SHA-256 用于接管确认，配置哈希用于与期望配置和既有基线比较。展示内容经递归脱敏，非法 JSON 仅显示占位符、文件大小与哈希。
2. `adopt-baseline` 在节点进程锁和数据库租约内重新读取远端文件。即使只改了 JSON 空白，原始 SHA-256 变化也返回 HTTP 409。成功后写入磁盘基线，清除运行态确认与终止重试状态。健康策略及覆盖继续取自最近一次成功应用。
3. 释放租约、带操作者的审计记录和待执行任务随基线更新在同一事务提交。任何一步失败都回滚。重发同一幂等键返回原任务。执行器仍会比较任务的期望哈希，并在远端替换前再次验证文件。
4. 对零字节或仅含空白的文件，清空两个语义基线字段，用初始基线保存原始 SHA-256。预检失败后仅同一份文件可以重试。成功应用后，正常回执替换初始基线。

## 失败引导

路由概览从节点配置状态和最新部署任务选取最近的失败原因与时间，向两种管理员角色提供相同的脱敏阶段摘要。基线冲突指向核对，配置或预检错误指向同步记录。对 SSH 或未知错误，节点列表比较最近 SSH 检查与失败的时间。最近一次检查成功且时间不早于失败时，列表显示查看失败原因的入口。
