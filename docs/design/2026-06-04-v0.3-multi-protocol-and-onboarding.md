# 多协议入站共存、节点一键接入与服务器更换架构

- **日期**：2026-06-04（涵盖后续 `v0.4.6` / `v0.4.8` / `v0.5.5` 同域演进）
- **状态**：Implemented（已落地于 `v0.3.0`、`v0.4.0`、`v0.4.4`、`v0.4.6`、`v0.4.8`、`v0.5.5`）
- **关联模块**：`pkg/types`、`internal/entity`、`internal/service/profile.go`、`internal/service/install.go`、`internal/service/subscribe*.go`、`internal/xray/config.go`、`scripts/node-bootstrap.sh`

---

## 1. 背景与核心问题

早期版本中单台节点仅能方便地运行单一协议默认端口，新购 VPS 需要手工配置 SSH 公钥、手工安装 Xray 再回到面板录入节点，服务器换 IP 或迁移重装时还会丢失分组与密钥关联。本系列演进围绕三个核心架构问题展开：

1. 同一台公网 VPS 如何安全运行多套入站协议（VLESS+Reality、VLESS+WS+TLS、Trojan、运维代理）而不发生端口冲突或订阅端口失配？
2. 节点控制面应演进为常驻 Agent（`xpilot-node`），还是基于无 Agent 的 SSH + 一次性令牌自动接入？
3. Hysteria2 与 HTTP/SOCKS5 运维代理各自与 Xray 内核及用户订阅的边界在哪里？

---

## 2. 多协议入站模板与节点级覆盖模型（v0.3.0 / v0.4.4）

### 2.1 声明式两层模型
- **协议模板（`InboundProfile`）**：定义跨节点共享的协议类型、默认端口与默认参数（如默认 Reality SNI、Fingerprint、WS Path）。
- **节点协议密钥（`NodeProfileKey`）**：维护 `Node × InboundProfile` 的绑定关系、AES-GCM 加密的节点专属密钥（Reality 私钥/ShortIds、TLS 证书路径）以及**节点级参数覆盖**（端口 `Port`、Reality `SNI` / `Fingerprint`）。

### 2.2 端口冲突护栏与消费方单一来源原则
- **按传输层独立编址**：`pkg/types.ProtocolTransport()` 将协议划分为 `TCP` 与 `UDP`。Service 层保存节点协议时校验 `(node_id, transport, effective_port)` 唯一性（例如 Reality `TCP/443` 可与 Hysteria2 `UDP/443` 共存，而同节点 Trojan 可覆盖至 `TCP/8443`）；`xray.GenerateConfig` 内置 `usedPorts` 二次兜底防脏数据导致 Xray 启动失败。
- **单一来源 Helper 铁律**：任何支持节点级覆盖的字段，配置生成与所有订阅格式（URI / Clash YAML / sing-box JSON）及健康探测必须调用同一套解析函数（`effectiveKeyPort`、`EffectiveRealitySNI`、`EffectiveRealityFingerprint`），严禁消费方各自直接读取模板默认字段。
- **双向对等抽屉交互**：同时提供「从协议视角批量绑定/生成多节点密钥（`Profiles.tsx`）」与「从单节点视角管理全部挂载协议（`Nodes.tsx` `xl` 抽屉）」两条对称操作路径。

## 3. 协议边界划分：Hysteria2 与 HTTP/SOCKS5 运维代理

### 3.1 Hysteria2 诚实边界（v0.3.0）
- **技术事实**：Hysteria2 属于 `apernet/hysteria` 独立服务端程序，Xray-core 不识别 `hysteria2` 入站协议。若强行写入 Xray `inbounds` 会导致整台节点 Xray 启动失败。
- **分层策略**：
  - 传输层分类、端口冲突校验、订阅链接（URI / Clash / sing-box）完整支持 Hysteria2 条目输出。
  - `internal/xray/config.go` 与 `LiveSyncService` 显式跳过/拒绝 Hysteria2，不混入 Xray 配置文件。

### 3.2 HTTP / SOCKS5 运维代理与安全隔离（v0.4.8）
- **定位**：仅供受信任的运行时程序或运维脚本作为固定出口使用，不属于普通 VPN 订阅协议。
- **三重护栏**：
  1. **防公网裸奔**：`buildProxyInbound` 强制要求 `allowed_ips`（源 IP/CIDR 白名单）与 `accounts`（账号密码认证）至少配置一项，否则拒绝生成该入站。
  2. **私网目标默认阻断与显式放行**：白名单通过 Xray 路由 `source` 规则实现；默认排在系统 `geoip:private -> block` 之后（禁止经代理探测节点内网）；仅当显式开启 `allow_private = true` 时，将该入站的白名单直连规则前置到 `geoip:private` 之前。
  3. **订阅与热同步隔离**：`/sub/:token` 全格式输出严格排除 `http` / `socks` 协议（由 `TestSubscriptionExcludesProxyProtocols` 单测锁定）；账号来自协议配置而非面板 `User` 表，`LiveSyncService` 跳过。

## 4. 无 Agent 一键接入与服务器更换架构（v0.4.0 / v0.4.6 / v0.5.5）

### 4.1 架构决策：保持 SSH 控制面，不做常驻 Agent
- 目标场景全部为具备公网 IP 的 VPS，无 NAT 内网穿透或成百上千节点的反向长连接诉求。引入独立 Agent 意味着额外的双向鉴权、版本兼容、自升级与离线降级复杂度。
- 决定继续采用 SSH 控制面，同时在实体与审计层预留无侵入扩展点（`Node.ConnectionMode` 默认 `"ssh"`、`Node.RegisteredAt`、日志 `Actor` 前缀规范）。

### 4.2 一次性安装令牌（`NodeInstallToken`）机制
- **安全约束**：32 字节高熵随机 Token，非管理员 JWT；默认 10 分钟 TTL、单次消费即失效、**首次拉取公钥时锁定请求源 IP**（后续 `register` 上报必须来自同一 IP，支持通过 `NODE_IP` 显式指定局域网/NAT 可达地址）。
- **单一配置源**：安装服务与系统自检统一从 `SettingService`（DB KV）读取 SSH 默认密钥路径并校验配套 `.pub` 公钥，避免静态 `config.yaml` 与运行时设置漂移。
- **锁定稳定 Xray 版本（v0.5.5）**：后台「节点与同步」维护目标稳定版本（默认 `26.3.27`），生成接入命令时固化 `XRAY_VERSION`，避免上游最新版破坏客户端或配置兼容性。

### 4.3 无缝更换节点服务器（v0.4.6）
- 当 VPS 被封 IP 或迁移机房时，支持在现有节点上发起「更换服务器」：
  - **仅换 IP**：直接更新连接地址并重新校验同步。
  - **重装接入（`replace_node_id`）**：安装令牌绑定原 `Node.ID`；新机器执行一键脚本回调 `registerReplace` 时，原地更新该节点的 IP、SSH 信息与初始配置基线，**原节点 ID 不变**，从而完整保留所属用户分组、`NodeProfileKey` 私钥材料及端口/SNI/路由覆盖。
