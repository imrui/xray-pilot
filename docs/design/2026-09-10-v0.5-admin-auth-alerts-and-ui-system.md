## 1. 多管理员账号系统与操作审计（v0.5.0）

### 1.1 从静态配置文件迁移至数据库权威模型
- **背景**：早期管理员账号硬编码于 `config.yaml` 内存列表，改密或多人协作需手工改文件重启服务，且操作日志无法区分具体执行人。
- **种子迁移策略**：新增 `admin_users` 表。仅当启动时表为空，读取 `config.yaml` 的 `admins` 列表初始化入库（首条记录设为 `super_admin`）；一旦表非空，启动时忽略配置文件中的 `admins` 段，完全以数据库为准，兼容旧部署零配置升级。

### 1.2 两级角色与无黑名单即时吊销
- **克制的权限分层（不上 RBAC、不做 TOTP）**：
  - `super_admin`：拥有系统全部权限，可管理管理员账号、重置他人密码、编辑全局路由模板及高风险系统路径。
  - `admin`：可执行日常节点、用户、分组、手动同步与节点域名覆盖操作，仅能修改自身密码，不可访问 `/api/admins/*` 或修改受保护的高级规则。
- **安全护栏**：禁止删除、禁用或降级最后一名处于启用状态的 `super_admin`；禁止删除、禁用自己或修改自己的角色。
- **即时失效机制**：不引入 Redis 或持久化的 JWT 黑名单表；JWT Claims 携带 `admin_id` 与 `role`，`JWTMiddleware` 每次请求按主键回查 `AdminUser.Active`（SQLite 单连接下开销可忽略），禁用或删除管理员后旧 Token 立即返回 `401`。

### 1.3 全链路 `Actor` 审计规范
- 废弃无操作者上下文的旧日志方法，全仓统一走 `LogRepository.RecordWithActor`。
- 命名约定：后台人工操作记为 `admin:<username>`，后台自动任务记为 `system:scheduler:<task>`，外部回调记为 `system:feishu-webhook` / `system:install-token:<prefix>`，支持在日志页按来源前缀检索。

## 2. 节点异常飞书群告警状态机（v0.5.1 / v0.5.2）

### 2.1 探测维度与跨境全挂防刷屏
复用现有飞书企业自建应用机器人（`chat_id` 群交互卡片），监控四类事件：

1. `node_unreachable`：SSH 端口连续 N 次（默认 3）探测失败。
2. `xray_down`：SSH 端口可达，但该节点挂载的任一启用 TCP 代理端口（经 `effectiveKeyPort` 解析）连续 N 次不可达；当轮 SSH 已失败时不推进 `xray_down`，避免单次宕机触发双重告警。
3. `sync_failed`：节点配置同步失败（阈值固定为 1，下次同步成功自动恢复）。
4. `panel_unreachable`（`node_id = 0`）：同一轮健康检测中，当启用节点数 `>= 2` 且**全部** SSH 不可达时，判定为面板所在网络出网故障，仅推进面板级告警，冻结各单节点计数，防止跨境链路抖动引发整屏告警风暴。

### 2.2 持久化状态机与并发字段级回写
- **表结构（`node_alert_states`）**：按 `(node_id, kind)` 唯一索引，分离记录**当前判定态 `Alerting`** 与**最近成功送达态 `NotifiedAlerting`**。
  - 当 `Alerting != NotifiedAlerting` 时表示存在待发通知；飞书 API 发送失败时不更新 `NotifiedAlerting`，下一轮 `Flush` 自动重试，无需额外消息队列。
  - 若故障在通知尚未发出的短暂窗口内已自行恢复（`Alerting` 回到 `false` 且此前 `NotifiedAlerting == false`），自动静默抵消，不会发出孤立的“已恢复”卡片。
- **并发防覆盖（v0.5.2 关键修复）**：
  - 由于 Service 实例按请求/任务动态构造，互斥锁（`alertStateMu` / `alertFlushMu`）必须定义为**包级锁**。
  - 状态推进使用 `SaveObservation`、飞书送达回写使用 `MarkNotified` 做**指定列级更新**，严禁在网络发送耗时结束后对结构体执行整行 `Save`（否则会把发送期间新一轮探测刚写入的“已恢复”状态重新覆盖回“告警中”）。
